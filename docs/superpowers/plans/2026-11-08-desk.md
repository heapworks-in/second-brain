# The desk — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** One ranked queue of proposals the app fills from data it already holds, worked one card at a time at `/desk`.

**Architecture:** A `proposals` table; seven pure `(db, now) => ProposalDraft[]` generators; `reconcileProposals` upserting by `(kind, sourceRef)`; an arithmetic ranker; a `desk` job on a 15-minute interval in `boot.ts`; one page.

**Tech Stack:** Next.js (this repo's version — read `node_modules/next/dist/docs/` before touching routes), drizzle + better-sqlite3, vitest, Tailwind tokens already in `globals.css`.

**Spec:** `docs/superpowers/specs/2026-11-08-desk-design.md`

## Global Constraints

- Generators are **pure and synchronous**: `(db: DB, now: Date) => ProposalDraft[]`. No provider, no network, no async. The embed provider can be off (`SB_EMBED=off`), so nothing may depend on it.
- Every date comparison takes `now` as an argument. No `new Date()` inside a generator, no fixed-date tests — `src/app/api/settings-calendar.test.ts` is the cautionary tale.
- No generator writes. `reconcileProposals` is the only writer of `proposals`; the per-kind commits in `decide.ts` are the only writers of anything else.
- A dismissed proposal must never reappear. The upsert is by `(kind, sourceRef)` and must not reset `state`.
- Buttons are named for their consequence. No generic "Accept" string anywhere in the UI.
- Personal content stays out of git: no fixture carries real meeting titles, task names or captures.

### Task 2: Rank and reconcile

**Files:**
- Create: `src/domain/desk/rank.ts`, `src/domain/desk/reconcile.ts`, `src/domain/desk/types.ts`
- Test: `src/domain/desk/rank.test.ts`, `src/domain/desk/reconcile.test.ts`

**Interfaces — produces:**

```ts
export interface ProposalDraft {
  kind: ProposalKind; source: string; sourceRef: string;
  title: string; detail: string; payload: unknown; urgency: number; // 0..1
}
export const OPEN_CAP = 7;
export function dismissRate(db: DB, kind: ProposalKind): number;       // last 30 decided
export function rankOf(db: DB, draft: ProposalDraft): number;          // urgency * weight * (1 - dismissRate)
export function reconcileProposals(db: DB, drafts: ProposalDraft[], now: Date): { opened: number; expired: number; returned: number };
```

The five transitions reconcile must get right, each its own test: new draft → `open`; same draft again → unchanged row, same `createdAt`; **a draft matching a `dismissed` row → still `dismissed`** (the one that matters); an `open` row with no matching draft → `expired`; a `snoozed` row past `snoozedUntil` → `open`. One transaction.

### Task 3: Generators — meetings and decisions

**Files:**
- Create: `src/domain/desk/generators/meeting-unprepared.ts`, `decision-stale.ts`, `commitment-unbooked.ts`, `index.ts`
- Test: one `.test.ts` beside each

Each test is table-driven with an injected `now`: fires / does not fire / does not fire twice.

- `meeting_unprepared` — `calendar_events` starting within 4h of `now`, `attendees > 1`, no `itemId`. `sourceRef: "event:{id}"`.
- `decision_stale` — `meeting_series_decisions` with `lastVerified` (falling back to `decidedAt`) older than the `desk.decisionStaleDays` setting (default 90). `sourceRef: "series:{seriesId}"`.
- `commitment_unbooked` — meeting items whose `meta.summary.proposed_actions` hold indices absent from `meta.acceptedActions`. `sourceRef: "action:{itemId}:{index}"`, so booking one does not dismiss the others.

### Task 4: Generators — tasks, predictions, captures

**Files:**
- Create: `src/domain/desk/generators/task-overrun.ts`, `task-stalled.ts`, `prediction-due.ts`, `capture-unfiled.ts`
- Test: one `.test.ts` beside each

- `task_overrun` — open task where `focusMinutesByTask` exceeds `estimateMinutes * 1.5`. Accept sets `estimateMinutes` to spent rounded to the nearest 15 (always available; `similarActualMinutes` needs a container and three matches, so it only ever decorates `detail`).
- `task_stalled` — open task with 3+ distinct `daily_plan_entries.date` and zero focus minutes. Accept removes it from today's plan.
- `prediction_due` — `duePredictions(db, localDay(now))`, unresolved. Accept opens the resolve step.
- `capture_unfiled` — `items` with `containerId` null, no `journalDate`/`reviewWeek`, older than `desk.captureUnfiledDays` (default 7). The suggested container is the container of the best `ftsSearch` hit on the item's title; **no suggestion means no proposal** — a card that cannot name where it would file is not a decision.

### Task 5: Deciding

**Files:**
- Create: `src/domain/desk/decide.ts`
- Test: `src/domain/desk/decide.test.ts`

**Interfaces — produces:**

```ts
export type Decision = "accept" | "snooze" | "dismiss";
export function decideProposal(db: DB, id: number, decision: Decision, now: Date): { proposal: Proposal; undo: () => void; label: string };
```

One `switch` on `kind` for the commit; each arm reuses existing domain functions (`createTask`, `updateItem`, `removeFromPlan`, `setSetting`) rather than writing SQL. `undo` restores `state` and reverses the commit — the page's eight-second line calls it. `dismiss` writes nothing beyond the row; the downweighting is `dismissRate` reading it later.

### Task 6: The sweep and the API

**Files:**
- Create: `src/jobs/handlers/desk.ts`, `src/app/api/desk/route.ts`, `src/app/api/desk/refresh/route.ts`, `src/app/api/desk/[id]/route.ts`
- Modify: `src/jobs/handlers/index.ts`, `src/server/boot.ts`, `src/lib/dto.ts`
- Test: `src/jobs/handlers/desk.test.ts`, `src/app/api/desk.test.ts`

`GET /api/desk` → `{ proposals: ProposalDTO[], counts }`. `POST /api/desk/refresh` enqueues the job. `POST /api/desk/[id]` takes `{ decision }` and answers the undo label; `DELETE /api/desk/[id]` is the undo. `crossSite` guard on every mutation, as the calendar route does.

Interval in `boot.ts` follows `distillSweepTick` exactly: `globalThis` guard, wrapped so a thrown generator never kills the timer, 15 minutes.
